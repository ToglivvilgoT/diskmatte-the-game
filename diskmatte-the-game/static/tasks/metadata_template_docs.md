# Template for Tasks Metadata Files

## File layout

The tasks files are split by course and learning set in the following way:

static/tasks/<course_slug>/<learning_set_slug>.json

## Task schema

Each learning set json file is a list of task objects.
Each task object has the following format:

```json
{
  "slug": "SlugField",
  "topic_slug": "optional, references Topic in same course",
  "title": "String",
  "prompt": "String",
  "instructions": "optional String",
  "expected_answer": "String (used for input_field, optional for others)",
  "hint": "optional String",
  "solution": "optional String",
  "image_url": "optional URL",
  "external_link": "optional URL",
  "book_reference": "optional String",
  "disk_reward": "optional PositiveInteger, default 100",
  "options": [
    {"label": "String", "is_correct": true}
  ]
}
```

### Validation and is_published

when populating the database, if all necessary fields are filled in,
the is_published is set to true.
Otherwise print an error message detailing what fields are missing on what object in what file.

### order

order should automatically go from 1 and up and should be the same as the order in the metadata file.

### answer_type

answer type should automatically get set based on how many options (if any) are set and if expected_answer is set.

- 0 options, expected_answer not set = checkbox
- 0 option, expected_answer set = input_field
- non zero options, expected_answer not set = multiple_choice

any other combination of options and expected_answers are invalid and
a debug message should be printed.

#### Extra validation for multiple_choice

For multiple_choice question:

- The position value of the options should be autogenerated from 1 and up and be the same order as provided in the metadata file.
- At least one option should have is_correct = true

## Updating

- If the metadata differs from the existing entry in the database,
update the existing entry with the new values.
- If metadata fields are missing that the database object has,
the database object should be updated and those fields removed.
- For the options list, if it differs, replace it in its entirety.

If this makes the object invalid (since it's missing required fields)
the object should be marked as is_published = false

## Missing slugs

If any of the slugs extracted from folder structure are missing from DB or
if the topic_slug is missing from DB an error message should be printed.

## Missing metadata

If metadata is missing for an existing task in the database,
mark it as is_published = false and print a warning.

## Errors

If any needed data is missing an error message should be printed so that an admin
or developer can fix the metadata.
Skip the erroneous file/folder and continue with the rest.
